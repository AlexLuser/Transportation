# 运输员服务（Driver Service）设计大纲

## 一、概述

### 1.1 服务定位
运输员服务（driver-service）是物流管理系统中负责运输员角色功能的核心服务，主要处理运输员的个人信息管理、订单配送、配送历史等功能。

### 1.2 技术栈
- **框架**: Spring Boot + Spring Cloud
- **数据库**: MySQL
- **ORM**: MyBatis-Plus
- **服务注册**: Nacos
- **API文档**: Swagger/OpenAPI
- **认证**: JWT（通过网关统一认证）

### 1.3 服务端口
- **开发环境**: 8086
- **网关路由**: `/api/drivers/**`

## 二、数据库设计

### 2.1 运输员信息表（driver_info）

```sql
CREATE TABLE `driver_info` (
  `id` BIGINT NOT NULL AUTO_INCREMENT COMMENT '运输员ID',
  `user_id` BIGINT NOT NULL COMMENT '关联user表的id（运输员用户）',
  `real_name` VARCHAR(50) NOT NULL COMMENT '真实姓名',
  `phone` VARCHAR(20) NOT NULL COMMENT '手机号',
  `email` VARCHAR(100) COMMENT '邮箱',
  `id_card` VARCHAR(18) COMMENT '身份证号',
  `gender` TINYINT COMMENT '性别：0=未知，1=男，2=女',
  `birthday` DATE COMMENT '生日',
  `avatar` VARCHAR(255) COMMENT '头像URL',
  `license_number` VARCHAR(50) COMMENT '驾驶证号',
  `license_type` VARCHAR(10) COMMENT '驾驶证类型（C1/C2/B1/B2等）',
  `license_expire_date` DATE COMMENT '驾驶证到期日期',
  `status` TINYINT DEFAULT 1 COMMENT '状态：0=禁用，1=启用，2=待审核',
  `create_time` DATETIME DEFAULT CURRENT_TIMESTAMP COMMENT '创建时间',
  `update_time` DATETIME DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP COMMENT '更新时间',
  PRIMARY KEY (`id`),
  UNIQUE KEY `uk_user_id` (`user_id`),
  INDEX `idx_phone` (`phone`),
  INDEX `idx_status` (`status`)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COMMENT='运输员信息表';
```

### 2.2 车辆信息表（vehicle_info）

```sql
CREATE TABLE `vehicle_info` (
  `id` BIGINT NOT NULL AUTO_INCREMENT COMMENT '车辆ID',
  `driver_id` BIGINT NOT NULL COMMENT '关联driver_info表的id',
  `vehicle_type` VARCHAR(20) NOT NULL COMMENT '车辆类型：小型货车/中型货车/大型货车/厢式货车等',

  `vehicle_model` VARCHAR(50) COMMENT '车辆型号',

  `load_capacity` DECIMAL(10, 2) COMMENT '载重（吨）',
  `volume_capacity` DECIMAL(10, 2) COMMENT '载货体积（立方米）',

  `create_time` DATETIME DEFAULT CURRENT_TIMESTAMP COMMENT '创建时间',
  `update_time` DATETIME DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP COMMENT '更新时间',
  PRIMARY KEY (`id`),
  INDEX `idx_driver_id` (`driver_id`),
  INDEX `idx_license_plate` (`license_plate`),
  INDEX `idx_vehicle_status` (`vehicle_status`)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COMMENT='车辆信息表';
```

### 2.3 订单配送表（order_delivery）

```sql
CREATE TABLE `order_delivery` (
  `id` BIGINT NOT NULL AUTO_INCREMENT COMMENT '配送ID',
  `order_id` BIGINT NOT NULL COMMENT '关联order_info表的id',
  `driver_id` BIGINT NOT NULL COMMENT '关联driver_info表的id（运输员）',
  `vehicle_id` BIGINT COMMENT '关联vehicle_info表的id（使用的车辆）',
  `delivery_status` TINYINT DEFAULT 0 COMMENT '配送状态：0=待接单，1=已接单，2=运输中，3=已送达，4=已取消',
  `accept_time` DATETIME COMMENT '接单时间',
  `pickup_time` DATETIME COMMENT '取货时间',
  `delivery_time` DATETIME COMMENT '送达时间',
  `cancel_time` DATETIME COMMENT '取消时间',
  `cancel_reason` VARCHAR(255) COMMENT '取消原因',
  `delivery_address` VARCHAR(500) COMMENT '配送地址（快照）',
  `receiver_name` VARCHAR(50) COMMENT '收货人姓名（快照）',
  `receiver_phone` VARCHAR(20) COMMENT '收货人电话（快照）',
  `remark` VARCHAR(500) COMMENT '配送备注',
  `create_time` DATETIME DEFAULT CURRENT_TIMESTAMP COMMENT '创建时间',
  `update_time` DATETIME DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP COMMENT '更新时间',
  PRIMARY KEY (`id`),
  UNIQUE KEY `uk_order_id` (`order_id`),
  INDEX `idx_driver_id` (`driver_id`),
  INDEX `idx_delivery_status` (`delivery_status`),
  INDEX `idx_create_time` (`create_time`)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COMMENT='订单配送表';
```

**说明**: 
- 订单配送表与订单表是一对一关系（一个订单对应一个配送记录）
- 当订单状态变为"已发货"时，系统自动创建配送记录，状态为"待接单"
- 运输员可以接单、更新配送状态

## 四、业务逻辑设计

### 4.1 订单配送流程

```
订单创建（已支付）
    ↓
订单状态：已支付 → 待发货
    ↓
商户发货，订单状态：待发货 → 已发货
    ↓
系统自动创建配送记录（delivery_status=0 待接单）
    ↓
运输员查看待接单订单列表
    ↓
运输员接单（delivery_status=1 已接单）
    ↓
运输员取货（delivery_status=2 运输中）
    ↓
运输员送达（delivery_status=3 已送达）
    ↓
订单状态：已发货 → 已完成
```

### 4.2 状态流转

**配送状态（delivery_status）**:
- `0` - 待接单：订单已发货，等待运输员接单
- `1` - 已接单：运输员已接单，准备取货
- `2` - 运输中：运输员已取货，正在配送
- `3` - 已送达：货物已送达，配送完成
- `4` - 已取消：配送被取消

**订单状态（order_status）关联**:
- 订单状态 `3`（已发货）→ 创建配送记录（待接单）
- 配送状态 `3`（已送达）→ 订单状态更新为 `4`（已完成）

### 4.3 权限控制

**网关权限配置**:
```java
// 运输员服务：只允许driver角色访问
if (path.startsWith("/api/drivers")) {
    return "driver".equals(roleCode) || "admin".equals(roleCode);
}
```

**业务权限**:
- 运输员只能查看和管理自己的信息
- 运输员只能接单和更新自己接的订单
- 管理员可以查看所有运输员信息

## 六、服务间调用

### 6.1 调用订单服务（Order Service）

**使用OpenFeign调用订单服务**:

```java
@FeignClient(name = "order-service", path = "/api/orders")
public interface OrderFeignClient {
    
    /**
     * 获取订单详情
     */
    @GetMapping("/{id}")
    Result<OrderDetailDTO> getOrderById(@PathVariable Long id);
    
    /**
     * 更新订单状态
     */
    @PutMapping("/{id}/status")
    Result<Boolean> updateOrderStatus(
        @PathVariable Long id,
        @RequestParam("status") Integer status
    );
}
```

**调用场景**:
- 接单时：获取订单详情，验证订单状态
- 更新配送状态时：同步更新订单状态
  - 取货（status=2）→ 订单状态保持"已发货"
  - 送达（status=3）→ 订单状态更新为"已完成"（status=4）

## 八、注意事项

### 8.1 数据一致性
- 配送状态更新时，需要同步更新订单状态
- 使用分布式事务或最终一致性保证数据一致性

### 8.2 并发控制
- 接单时需要考虑并发问题（多个运输员同时接同一个订单）
- 可以使用数据库乐观锁或分布式锁

### 8.3 性能优化
- 配送订单列表查询需要分页
- 可以添加缓存（Redis）缓存运输员信息和车辆信息

### 8.4 安全性
- 运输员只能操作自己的信息
- 接单时需要验证订单状态
- 更新配送状态时需要验证权限（只能更新自己接的订单）

## 十二、总结

运输员服务是物流管理系统中连接订单和实际配送的关键服务，主要职责包括：
1. **个人信息管理**：维护运输员基本信息和证件信息
2. **车辆管理**：管理运输员的车辆信息
3. **订单配送**：接单、配送、状态更新

服务设计遵循微服务架构原则，通过OpenFeign与其他服务（订单服务）进行交互，保证系统的解耦和可扩展性。
